# Commodore 64 / 6510

The 6510 is the C64's 6502-compatible CPU. `compile_and_diff` accepts 6510 assembly directly; use one instruction
per line with ordinary py65 syntax, such as `LDA #$01`, `STA $D020` or `BNE $C012`. `.byte $xx, $yy` is useful
for bytes that are data or instructions the disassembler could not reach. Branch operands are absolute target
addresses, not signed offsets. The assembler starts at the routine's original address, so relative branches are
encoded for that location.

Agents can also submit a C function. It is compiled (`cc65 -t c64 -O`) and linked at the routine's original address
with cc65. Choose "C with cc65" as the project's compiler (when importing, or later in Settings) to make C the goal;
decomp.wtf installs cc65 for you on Windows, elsewhere put `cc65`, `ca65` and `ld65` on PATH. A C function has the
routine's name (`func_6600`), declares what it calls (`extern void func_6756(void);`) and reaches hardware through
pointers (`*(volatile unsigned char *)0xD020 = 0;`). The C path is most useful for code originally built with cc65.

Inline `asm` is not allowed, but cc65's register pseudo-variables are plain C: `__A__`, `__AX__` and `__EAX__` read and
write the accumulator (A, A/X, A/X/sreg). Use them for small routines that take or return values in registers, which is
how many stubs and library helpers look. Verified: `void func_A726(void) { __A__ += 0x19; }` compiles to exactly
`clc / adc #$19 / rts`. Do not use `__fastcall__` parameters for this: cc65 spills them to the C stack (`jsr pusha`).
Compare `__A__ += n` (emits `clc; adc #n`) with `__A__ = __A__ + n` (calls a helper) and try both forms.
Hand-written assembly is the normal case for C64 games, and stays the default.

Functions are discovered from the program's entry address (a BASIC `SYS` line when present, otherwise the PRG load
address) by following branches and direct `JSR` calls. Indirect calls, jump tables and unreachable code may need
manual recovery; a missing routine can be added by splitting a neighboring function.

TAP tape images aren't read directly. Extract PRGs from them first with TAPClean (command line) or TAPClean FE
(`tapcleanfe`, GUI), https://sourceforge.net/projects/tapclean/, then import the `.prg`, or the whole folder of
PRGs at once (programs with no reachable code are skipped; repeated programs and routines are imported once).

The C64 has 64 KiB of address space, memory-mapped I/O and no universal C calling convention. Use the target
listing and surrounding routines to infer register use, stack conventions and hardware accesses. Addresses in
disassembly are absolute C64 addresses.
